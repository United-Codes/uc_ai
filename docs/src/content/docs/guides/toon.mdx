**Token-Oriented Object Notation (TOON)** is a compact and readable encoding of the JSON data model. It uses fewer tokens, and a model can follow its structure easily. TOON is a lossless representation of your existing JSON, for LLM input.

TOON takes the indentation structure of YAML for a nested object, and a CSV-style table layout for a uniform array. TOON works best for a uniform array of objects, that is several fields per row and the same structure in every item. Such an array is as compact as CSV, and its explicit structure helps an LLM parse and validate the data.

<Aside type="tip">
  TOON is a translation layer. Use JSON in your code, and encode it as TOON for
  LLM input.
</Aside>

## Why Use TOON?

Every token counts when you send data to an LLM:

- **Cost reduction**: fewer tokens give a lower API cost
- **Context efficiency**: more room for content in the context window
- **Better parsing**: the structured format helps an LLM read and use the data

The similarity to CSV is intentional. CSV is simple and well known, and TOON keeps that familiarity. TOON is still a lossless representation of JSON for a Large Language Model.

<Aside type="caution">
  For deeply nested data, or for data without a uniform structure, use JSON. It
  can need fewer tokens. TOON works best for a uniform array of objects.
</Aside>

## TOON Format Rules

### Simple Objects

An object uses the YAML-style `key: value` notation, with a newline between the properties:

```
name: Alice
age: 30
```

This is the same as the JSON `{"name": "Alice", "age": 30}`

### Nested Objects

A nested object uses indentation, with 2 spaces for each level:

```
user:
  name: Bob
  contact:
    email: bob@ex.com
```

### Primitive Arrays

An array of primitives is inline, with a count:

```
[3]: 1,2,3
```

This is `[1, 2, 3]`.

### Homogeneous Object Arrays (Tabular Format)

An array of objects with the same structure uses a CSV-style column format:

```
[2]{id,active}:
  1,true
  2,false
```

This is `[{"id": 1, "active": true}, {"id": 2, "active": false}]`.

### Irregular Arrays

An array with mixed structures uses the dash notation:

```
[3]:
  - a: 1
  - a: 1
    b: 2
  - c: 3
```

### Special Values

- **Null values**: `null`
- **Booleans**: `true` or `false`
- **Empty arrays**: `key[0]:`
- **Empty objects**: `key:`
- **Strings with special characters**: in quotes, with escapes, for example `"He said \"hello\""`

## Using TOON in UC AI

The `uc_ai_toon` package converts JSON to the TOON format.

### Converting a Single Row to TOON

Use `JSON_OBJECT` to build a JSON object from one row. Then convert it to TOON:

```sql
DECLARE
  l_json json_object_t;
  l_toon clob;
BEGIN
  SELECT json_object(
           'employee_id' value employee_id,
           'first_name'  value first_name,
           'last_name'   value last_name,
           'salary'      value salary
         )
    INTO l_json
    FROM employees
   WHERE employee_id = 100;

  l_toon := uc_ai_toon.to_toon(l_json);

  dbms_output.put_line(l_toon);
  -- Output:
  -- employee_id: 100
  -- first_name: Steven
  -- last_name: King
  -- salary: 24000
END;
/
```

### Converting Multiple Rows to TOON

Use `JSON_ARRAYAGG` to aggregate several rows into a JSON array:

```sql
DECLARE
  l_json json_array_t;
  l_toon clob;
BEGIN
  SELECT json_arrayagg(
           json_object(
             'department_id'   value department_id,
             'department_name' value department_name,
             'manager_id'      value manager_id
           )
         )
    INTO l_json
    FROM departments
   WHERE location_id = 1700;

  l_toon := uc_ai_toon.to_toon(l_json);

  dbms_output.put_line(l_toon);
  -- Output (homogeneous array uses tabular format):
  -- [7]{department_id,department_name,manager_id}:
  --   10,Administration,200
  --   30,Purchasing,114
  --   90,Executive,100
  --   ...
END;
/
```

### Converting a JSON String

You can also pass a JSON string as a `CLOB`:

```sql
DECLARE
  l_json_str clob;
  l_toon clob;
BEGIN
  -- Query returning JSON as string
  SELECT json_object(
           'count' value count(*),
           'avg_salary' value round(avg(salary), 2)
         returning clob)
    INTO l_json_str
    FROM employees;

  l_toon := uc_ai_toon.to_toon(l_json_str);

  dbms_output.put_line(l_toon);
  -- Output:
  -- count: 107
  -- avg_salary: 6461.83
END;
/
```

## Practical Example: Sending Data Context to LLM

This example sends database rows to an LLM as TOON, with few tokens:

```sql
DECLARE
  l_products json_array_t;
  l_toon_data clob;
  l_result json_object_t;
  l_response clob;
BEGIN
  -- Build product data using JSON SQL functions
  SELECT json_arrayagg(
           json_object(
             'id'    value product_id,
             'name'  value product_name,
             'price' value list_price,
             'stock' value quantity_on_hand
           )
           ORDER BY product_name
         )
    INTO l_products
    FROM products p
    JOIN inventories i ON p.product_id = i.product_id
   WHERE category_id = 1  -- Electronics
   FETCH FIRST 10 ROWS ONLY;

  -- Convert to TOON for token efficiency
  l_toon_data := uc_ai_toon.to_toon(l_products);

  -- Send to LLM with TOON-formatted context
  l_result := uc_ai.generate_text(
    p_system_prompt => 'You are analyzing product inventory data provided in TOON format (a compact JSON representation).',
    p_user_prompt => 'Here is our current electronics inventory:' || chr(10) ||
                     l_toon_data || chr(10) || chr(10) ||
                     'Which products are running low on stock (less than 10 units)?',
    p_provider => uc_ai.c_provider_openai,
    p_model => uc_ai_openai.c_model_gpt_4o_mini
  );

  l_response := l_result.get_clob('final_message');
  dbms_output.put_line(l_response);
END;
/
```

## Complex Example: Nested Data Structures

TOON also encodes a complex nested structure. Use nested `JSON_OBJECT` and `JSON_ARRAYAGG` calls:

```sql
DECLARE
  l_json json_object_t;
  l_toon clob;
BEGIN
  -- Build nested JSON with departments and their employees
  SELECT json_object(
           'department'  value department_name,
           'manager'     value (
             SELECT json_object(
                      'id'   value e.employee_id,
                      'name' value e.first_name || ' ' || e.last_name
                    )
               FROM employees e
              WHERE e.employee_id = d.manager_id
           ),
           'employee_count' value (
             SELECT count(*)
               FROM employees e
              WHERE e.department_id = d.department_id
           )
         )
    INTO l_json
    FROM departments d
   WHERE department_id = 90;

  l_toon := uc_ai_toon.to_toon(l_json);

  dbms_output.put_line(l_toon);
  -- Output:
  -- department: Executive
  -- manager:
  --   id: 100
  --   name: Steven King
  -- employee_count: 3
END;
/
```

## API Reference

### `uc_ai_toon.to_toon` (JSON Object)

```sql
function to_toon(p_json_object in json_object_t) return clob;
```

Converts a `json_object_t` to TOON format.

**Parameters:**

- `p_json_object`: The JSON object to convert

**Returns:** a CLOB with the TOON representation

### `uc_ai_toon.to_toon` (JSON Array)

```sql
function to_toon(p_json_array in json_array_t) return clob;
```

Converts a `json_array_t` to TOON format.

**Parameters:**

- `p_json_array`: The JSON array to convert

**Returns:** a CLOB with the TOON representation

### `uc_ai_toon.to_toon` (JSON String)

```sql
function to_toon(p_json_string in clob) return clob;
```

Converts a JSON string (CLOB) to TOON format.

**Parameters:**

- `p_json_string`: The JSON string to convert

**Returns:** a CLOB with the TOON representation

<Aside type="note">
  Every `to_toon` function returns `null` for a `null` input.
</Aside>

## When to Use TOON

| Scenario                                   | Recommendation                                |
| ------------------------------------------ | --------------------------------------------- |
| Uniform arrays of objects (same structure) | ✅ **Use TOON** - the largest token saving     |
| Tabular data from database queries         | ✅ **Use TOON** - as compact as CSV            |
| Simple flat objects                        | ✅ **Use TOON** - clearer than JSON            |
| Deeply nested irregular structures         | ⚠️ Use JSON - it can need fewer tokens         |
| Non-uniform arrays with varied schemas     | ⚠️ Use JSON - the TOON header adds no value    |
| Data that the LLM returns                  | ❌ **Use JSON** - the standard format to parse  |
